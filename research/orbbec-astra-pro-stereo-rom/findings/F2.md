# F2: Stereo/depth calibration techniques

## Findings

### [1] OpenCV `calibrateCamera` uses Zhang's method to estimate intrinsic matrix K (fx, fy, cx, cy), distortion coefficients (k1-k6, p1, p2, s1-s4), and per-image rotation/translation vectors from known 3D-2D correspondences on a calibration pattern.
- quote: "The process of estimating the parameters of a camera is called camera calibration... the intrinsic matrix K is upper triangular [fx 0 cx; 0 fy cy; 0 0 1]... The implementation is based on a paper by Zhengyou Zhang."
- url: https://learnopencv.com/camera-calibration-using-opencv/
- source_type: secondary
- published: 2020-02-25 (updated 2026-07-31)
- confidence: high

### [2] ChArUco boards produce more accurate corner localizations than plain checkerboards or ArUco markers, making them the recommended calibration target for OpenCV-based calibration, especially when partial views or occlusions are expected.
- quote: "It is highly recommended using the ChArUco corners approach since the provided corners are much more accurate in comparison to the marker corners. Calibration using a standard Board should only be employed in those scenarios where the ChArUco boards cannot be employed."
- url: https://docs.opencv.org/4.13.0/da/d13/tutorial_aruco_calibration.html
- source_type: primary
- published: 2025-12-31 (OpenCV 4.13.0 docs)
- confidence: high

### [3] The Orbbec Astra SDK (v2.1.3, used by original Astra Pro) reached End-of-Life in 2022Q3 with no further updates or support. The recommended migration path for newer Orbbec devices is Orbbec SDK v2 (current: v2.9.3), which is open-source.
- quote: "Astra SDK... EOL Version: 2.1.3... End of Support 2022Q3. All current functions and camera will not be affected, no further update and support."
- url: https://www.orbbec.com/developers/astra-sdk/
- source_type: primary
- published: unknown (page current as of 2026-10)
- confidence: high

### [4] The Orbbec SDK v1 (1.10.27) supports the Astra Pro Plus and legacy devices, while Orbbec SDK v2 (2.9.3) supports newer devices (Gemini 335/336, Astra 2, Femto series). The original Astra Pro is NOT listed in either SDK v1 or v2 device support lists, suggesting it may only work via the EOL Astra SDK or OpenNI.
- quote: "Orbbec SDK v2 for Windows(Recommended)... Supports Gemini 305g, Gemini 305, Gemini 345... Astra Mini (S) Pro, Gemini 435Le... Femto Mega(I), Femto Bolt, Astra 2" and "Orbbec SDK for Windows... Supports DaBai(DCW/DW), Astra Pro Plus, Gemini, Astra+..."
- url: https://www.orbbec.com/developers/orbbec-sdk/
- source_type: primary
- published: unknown (page current as of 2026-10)
- confidence: high

### [5] The Orbbec Python SDK (pyorbbecsdk, v2.x on PyPI as `pyorbbecsdk2`) provides depth-color alignment via software `AlignFilter` and hardware D2C, point cloud generation via `PointCloudFilter`, and access to camera calibration intrinsics/distortion/extrinsics data.
- quote: "Depth-color alignment — Software AlignFilter and hardware D2C alignment. Point cloud generation — Colored 3D point clouds via PointCloudFilter. Camera calibration data — Access intrinsics, distortion coefficients, and extrinsic transforms."
- url: https://github.com/orbbec/pyorbbecsdk
- source_type: primary
- published: unknown (repository active, v2-main branch)
- confidence: high

### [6] OpenCV's `cv::undistort` and `cv::initUndistortRectifyMap`+`cv::remap` are the two standard approaches for distortion correction. The latter precomputes remap tables once for video streams and is the recommended approach for real-time processing of repeated frames from the same camera configuration.
- quote: "`undistort` computes and applies the mapping in one call. It is convenient for an occasional still image. `initUndistortRectifyMap` computes the maps once, then `remap` reuses them. This is the better structure for a video stream or many images with the same resolution and camera configuration."
- url: https://learnopencv.com/camera-calibration-using-opencv/
- source_type: secondary
- published: 2020-02-25 (updated 2026-07-31)
- confidence: high

### [7] The Orbbec SDK v2 includes built-in `UnDistortionFilter` as a depth post-processing filter, available for supported devices (e.g., Gemini 330 series), which may reduce the need for custom OpenCV-based distortion correction for depth streams.
- quote: "Added FalsePositiveFilter support for Gemini 330 series devices, the general-purpose UnDistortionFilter, and DispOutliersFilter support for DaBai Max series devices."
- url: https://www.orbbec.com/developers/orbbec-sdk/
- source_type: primary
- published: unknown (Orbbec SDK v2.9.3 release notes)
- confidence: medium

### [8] For structured light depth cameras (like Astra Pro), depth-to-RGB alignment requires the extrinsic transformation between the IR/depth sensor and the RGB sensor, plus individual intrinsic calibration for each sensor. The standard approach uses OpenCV's `stereoCalibrate` to jointly estimate the relative pose between two cameras.
- quote: "Estimate the relative position and orientation of the stereo camera 'heads' and compute the rectification transformation that make the camera optical axes parallel." The OpenCV calib3d module provides `stereoCalibrate` for this purpose.
- url: https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html
- source_type: primary
- published: 2025-12-31 (OpenCV 4.13.0 docs)
- confidence: high

### [9] A validated checkerboard calibration using 41 images at 640x480 resolution achieved an RMS reprojection error of 0.2603 pixels with OpenCV, yielding intrinsics fx=503.51, fy=503.15, cx=313.41, cy=243.09 — demonstrating that sub-pixel calibration accuracy is achievable with standard checkerboard patterns.
- quote: "Matched images: 41, Complete checkerboards: 41, OpenCV calibration RMS: 0.260320101 pixels... fx: 503.5118 pixels, fy: 503.1461 pixels, cx: 313.4135 pixels, cy: 243.0911 pixels"
- url: https://learnopencv.com/camera-calibration-using-opencv/
- source_type: secondary
- published: 2020-02-25 (updated 2026-07-31)
- confidence: high

### [10] The pyorbbecsdk Python SDK (v2) exposes a beginner-level calibration example and alignment example among its 35+ example scripts, including depth-color alignment, calibration data extraction, and point cloud generation — providing a direct Python path for the Orbbec depth-to-RGB pipeline.
- quote: "Beginner: Hello camera, depth viz, alignment, calibration, point cloud, multi-stream, IMU, network camera, and firmware update."
- url: https://github.com/orbbec/pyorbbecsdk
- source_type: primary
- published: unknown (repository active)
- confidence: high

### [11] OpenCV supports multiple distortion models beyond the standard pinhole: rational (k1-k6), thin prism (s1-s4), tilted sensor (Scheimpflug), and fisheye models. The `CALIB_RATIONAL_MODEL` flag enables the extended radial distortion model which is important for wide-angle or low-cost depth camera lenses.
- quote: "The distortion parameters are the radial coefficients k1, k2, k3, k4, k5, and k6, p1 and p2 are the tangential distortion coefficients, and s1, s2, s3, and s4, are the thin prism distortion coefficients."
- url: https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html
- source_type: primary
- published: 2025-12-31 (OpenCV 4.13.0 docs)
- confidence: high
