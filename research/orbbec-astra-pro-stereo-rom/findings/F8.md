# F8: Implementation & latency

## Findings

### [1] RTMPose pose-only inference on Jetson AGX Orin (TensorRT FP16) ranges from 1.63ms (tiny) to 3.67ms (large) at 256x192 input
- quote: "RTMPose-t ... TRT-FP16 (Jetson AGX Orin) 1.63 ... RTMPose-m ... 2.72 ... RTMPose-l ... 3.67"
- url: https://github.com/open-mmlab/mmpose/blob/main/projects/rtmpose/benchmark/README.md
- source_type: primary
- published: 2023 (benchmarks updated through 2023-2024)
- confidence: high

### [2] RTMPose on Jetson Orin NX (TensorRT FP16) is ~15-30% slower than AGX Orin: 1.97ms (tiny) to 4.78ms (large)
- quote: "RTMPose-t ... TRT-FP16 (Jetson Orin NX) 1.97 ... RTMPose-m ... 3.35 ... RTMPose-l ... 4.78"
- url: https://github.com/open-mmlab/mmpose/blob/main/projects/rtmpose/benchmark/README.md
- source_type: primary
- published: 2023
- confidence: high

### [3] Full RTMPose pipeline (RTMDet-nano detection + RTMPose-m pose) achieves 73.2 AP on COCO with combined latency of 4.31ms on GTX 1660Ti (TRT-FP16) and 26.6ms on i7-11700 (ONNX Runtime)
- quote: "Detection Config: RTMDet-nano ... Pose Config: RTMPose-m ... Pipeline AP(COCO) 73.2 ... ORT-Latency(ms)(i7-11700) 26.613 ... TRT-FP16-Latency(ms)(GTX 1660Ti) 4.312"
- url: https://github.com/open-mmlab/mmpose/tree/main/projects/rtmpose
- source_type: primary
- published: 2023
- confidence: high

### [4] Orbbec SDK v2 officially supports NVIDIA Jetson AGX Orin, Orin NX, Orin Nano, AGX Xavier, Xavier NX, and Thor on Linux ARM64
- quote: "Linux ARM64: tested on NVIDIA Jetson AGX Orin, NVIDIA Jetson Orin NX, NVIDIA Jetson Orin Nano, NVIDIA Jetson AGX Xavier, NVIDIA Jetson Xavier NX, NVIDIA Jetson Thor"
- url: https://github.com/orbbec/OrbbecSDK_v2
- source_type: primary
- published: 2026 (active development, last updated Oct 2026)
- confidence: high

### [5] Orbbec SDK v2 supports V4L2 backend on Linux for better performance and lower resource consumption than default LibUVC
- quote: "For cameras connected via USB, the Orbbec SDK supports both LibUVC and V4L2 as backends, with the V4L2 backend generally offering better performance and lower resource consumption. However, the V4L2 backend may have compatibility issues with different Linux versions, which is why the Orbbec SDK defaults to using the LibUVC backend."
- url: https://github.com/orbbec/OrbbecSDK_v2/blob/main/docs/tutorial/performance_tuning.md
- source_type: primary
- published: 2026
- confidence: high

### [6] Orbbec recommends increasing usbfs_memory_mb to 128MB for multi-device or high data-rate USB streaming scenarios
- quote: "It is strongly recommended to increase the usbfs_buffer_size parameter when using multiple usb devices or when streaming large amounts of data, as the default value may not be sufficient to handle the data rate. ... echo 128 | sudo tee /sys/module/usbcore/parameters/usbfs_memory_mb"
- url: https://github.com/orbbec/OrbbecSDK_v2/blob/main/docs/tutorial/performance_tuning.md
- source_type: primary
- published: 2026
- confidence: high

### [7] Orbbec's LingBot Enhanced Depth Filter (color+depth denoising, hole-filling, edge refinement) is only supported on NVIDIA Jetson running JetPack 6.2
- quote: "LingBot Enhanced Depth Filter uses color and depth information to reduce noise, fill depth holes, and refine object edges. This feature is supported on NVIDIA Jetson running JetPack 6.2."
- url: https://github.com/orbbec/OrbbecSDK_v2
- source_type: primary
- published: 2026
- confidence: high

### [8] Orbbec OpenNI SDK is in "limited maintenance" status; Orbbec SDK v2 is the recommended path for new designs and all current devices
- quote: "OpenNI SDK (Limited Maintenance)" ... device support table shows "Astra Pro Plus: limited maintenance" and newer devices marked "not supported" for OpenNI
- url: https://github.com/orbbec/OrbbecSDK_v2 and https://www.orbbec.com/developers/openni-sdk/
- source_type: primary
- published: 2026
- confidence: high

### [9] Orbbec is migrating devices from OpenNI protocol to UVC protocol (starting Oct 2025 with SDK v2.5.5), making Orbbec SDK v2 the only compatible SDK for upgraded firmware
- quote: "Starting from October 2025 (Orbbec SDK v2.5.5), we will begin upgrading devices that use the OpenNI protocol to the UVC protocol, enabling full compatibility with Orbbec SDK v2."
- url: https://github.com/orbbec/OrbbecSDK_v2
- source_type: primary
- published: 2026
- confidence: high

### [10] RTMPose supports MMDeploy with TensorRT and ncnn backends on NVIDIA Jetson and ARM platforms, making it directly deployable on edge devices
- quote: "With the help of MMDeploy, our project supports various platforms like CPU, GPU, NVIDIA Jetson, and mobile devices and multiple inference backends such as ONNXRuntime, TensorRT, ncnn, etc."
- url: https://github.com/open-mmlab/mmpose/tree/main/projects/rtmpose
- source_type: primary
- published: 2023
- confidence: high

### [11] RTMPose on Snapdragon 865 (ncnn FP16) achieves 9.02ms (tiny) to 45.37ms (large) latency, showing that mobile ARM can handle real-time pose estimation but with significantly higher latency than Jetson
- quote: "ncnn-FP16 (Snapdragon 865) ... RTMPose-t 9.02 ... RTMPose-s 13.89 ... RTMPose-m 26.44 ... RTMPose-l 45.37"
- url: https://github.com/open-mmlab/mmpose/blob/main/projects/rtmpose/benchmark/README.md
- source_type: primary
- published: 2023
- confidence: high

### [12] RK3588 has no official RTMPose benchmark in the MMPose repository; Snapdragon 865 benchmarks (ARM Cortex-A77) provide a conservative proxy since RK3588's Cortex-A76 cores have comparable single-thread performance
- quote: (no direct RK3588 benchmark found in official sources)
- url: https://github.com/open-mmlab/mmpose/blob/main/projects/rtmpose/benchmark/README.md
- source_type: primary (inference from available benchmarks)
- published: 2023
- confidence: medium

## Dead ends
- No direct OpenNI2 vs Orbbec SDK v2 benchmark comparison was found in official documentation
- No RK3588-specific RTMPose or depth camera benchmark data was found in primary sources
- No published latency figures for depth frame acquisition overhead on Jetson/RK3588 from Orbbec
- No direct point-cloud-processing overhead benchmarks from Orbbec SDK on ARM64

## Suggested follow-ups
- Benchmark actual end-to-end pipeline latency on target hardware (Jetson Orin NX or RK3588): depth frame acquisition + alignment + RTMPose inference + depth lookup at 2D keypoint coordinates
- Investigate Open3D or PCL point cloud filtering overhead on ARM64 for the depth-to-3D conversion step (not addressed by Orbbec SDK benchmarks)
- Test whether the Orbbec SDK V4L2 backend resolves any frame-dropping issues on Jetson specifically for 30fps depth+color streaming
